# Luxfly ✈️ — Playwright Testing Workshop App

Luxfly is a realistic flight-booking demo built with vanilla HTML/CSS/JS. All data (136 airports, 176 flights, users, coupons) lives in a JavaScript in-memory store (`_DB`) and is served to the browser through a **Mock Service Worker (MSW)** that intercepts real `fetch()` calls to `/api/*` endpoints — no backend required, but real HTTP semantics throughout. Designed as a **hands-on testing workshop** — every interactive element carries a `data-testid` attribute, the seed data gives you rich scenarios to automate, and Playwright can intercept or override any API endpoint.

## Quick Start

### Prerequisites

- Node.js 24+ and pnpm

### Local server (required)

MSW registers a service worker at `/mockServiceWorker.js`. Service workers only work over HTTP — opening `index.html` directly as a `file://` URL will not work.

```bash
pnpm install
pnpm start          # serves public/ at http://localhost:3000
```

Open **http://localhost:3000** in your browser.

> **No backend required.** All data lives in the `_DB` object inside `public/js/app.js` and is served exclusively by the MSW service worker. No real network calls leave the browser.

## How MSW Works

### Script load order (all pages)

Every HTML page loads scripts in this order:

```html
<script src="https://unpkg.com/msw@3/browser/index.js"></script>  <!-- exposes window.MSW -->
<script src="js/app.js?v=3"></script>                              <!-- defines _DB, fetch helpers, waitForMSW() -->
<script src="js/msw-handlers.js?v=1"></script>                     <!-- registers handlers, starts service worker -->
<script src="js/results.js?v=3"></script>                          <!-- (page-specific script, runs last) -->
```

### Readiness handshake

`msw-handlers.js` calls `worker.start()` (async), then:
- sets `window.__mswReady = true`
- dispatches a `msw:ready` custom event on `window`
- exposes `window.__mswWorker` so Playwright tests can call `worker.use()` or `worker.resetHandlers()`

Every page script's `DOMContentLoaded` handler begins with:

```js
await waitForMSW();   // resolves immediately on repeat page loads; 3 s fallback if CDN blocked
```

This guarantees the service worker is active before any `fetch('/api/...')` call is made.

### Data flow

```
Page JS  ──fetch('/api/flights?...')──▶  MSW service worker
                                              │
                                              ▼
                                         _DB.flights  (in-memory, app.js)
                                              │
                                    HttpResponse.json(...)
                                              │
         Page JS  ◀──────────────────────────┘
```

Bookings written via `POST /api/bookings` are pushed onto `_DB.bookings` and also persisted to `localStorage` (`lf_bookings`) so they survive soft navigations within the tab. `_DB` resets to seed data on a full page reload.

## API Contract

All `/api/*` routes are intercepted by MSW in `public/js/msw-handlers.js`. There is no real backend — these routes never leave the browser.

### Endpoints

#### `GET /api/airports`
Returns all 136 airports.

**Response `200`**
```json
[{ "id": "SYD", "name": "Kingsford Smith International Airport", "city": "Sydney", "country": "Australia" }]
```

---

#### `GET /api/flights`
Returns flights, optionally filtered.

**Query params**

| Param | Description |
|-------|-------------|
| `origin` | IATA code, e.g. `SYD` |
| `destination` | IATA code, e.g. `MEL` |
| `cabinClass` | `Economy` \| `Business` \| `First` |

**Response `200`** — array of Flight objects (see [Object shapes](#object-shapes)).

---

#### `GET /api/flights/:id`
Returns a single flight by ID.

**Response `200`** — Flight object  
**Response `404`** — if not found

---

#### `GET /api/bookings`
Returns all bookings in `_DB.bookings` (admin / agent use). No auth enforcement in the mock.

**Response `200`** — array of Booking objects

---

#### `POST /api/bookings`
Creates and stores a new booking.

**Request body** — Booking input object  
**Response `201`** — saved Booking with generated `id` and `bookedAt`

---

#### `GET /api/users`
Returns all users, with `password` field stripped (admin use).

**Response `200`** — array of User objects (no password field)

---

#### `POST /api/auth/login`
Authenticates a user.

**Request body**
```json
{ "email": "mick.passenger@luxfly.test", "password": "Mick1234" }
```
**Response `200`** — User object (no password)  
**Response `401`** — `{ "error": "Invalid email or password." }`

---

#### `POST /api/auth/register`
Creates a new user account.

**Request body**
```json
{ "firstName": "Jane", "lastName": "Doe", "email": "jane@test.com", "password": "Jane1234", "role": "passenger" }
```
**Response `201`** — new User object (no password)  
**Response `409`** — `{ "error": "An account with this email already exists." }`

---

#### `GET /api/coupons`
Returns coupons, optionally filtered by role.

**Query params**

| Param | Description |
|-------|-------------|
| `role` | When provided, returns only active coupons where `applicableRoles` includes this role |

**Response `200`** — array of Coupon objects

### Object shapes

#### Flight

```json
{
  "id": "F001",
  "airline": "Auster Airways",
  "flightNumber": "QF401",
  "origin": "SYD",
  "destination": "MEL",
  "departureTime": "06:00",
  "arrivalTime": "07:30",
  "duration": "1h 30m",
  "stops": 0,
  "stopCity": null,
  "price": 129,
  "seatsAvailable": 14,
  "class": ["Economy", "Business"]
}
```

- `stops`: `0` = direct, `1` = one stop (no multi-stop in seed data)
- `stopCity`: IATA code of the intermediate airport, or `null`
- `class`: always an array; possible values are `"Economy"`, `"Business"`, `"First"`

#### Airport

```json
{
  "id": "SYD",
  "name": "Kingsford Smith International Airport",
  "city": "Sydney",
  "country": "Australia"
}
```

#### Coupon

```json
{
  "id": "C001",
  "code": "WELCOME10",
  "description": "Welcome offer — 10% off your first booking",
  "discountType": "percentage",
  "discountValue": 10,
  "applicableRoles": ["passenger"],
  "active": true
}
```

`discountType` values:
- `"percentage"` — reduces total by `discountValue`%
- `"fixed"` — reduces total by `discountValue` AUD
- `"upgrade"` — cabin class upgrade perk, no price change

#### Booking (output from `POST /api/bookings`)

```json
{
  "id": "BK1728000000000",
  "reference": "LX-ABC123",
  "flightId": "F001",
  "userId": "U001",
  "passengers": [
    {
      "title": "Mr",
      "firstName": "John",
      "lastName": "Smith",
      "dob": "1990-05-15",
      "passport": "PA1234567",
      "nationality": "Australia",
      "type": "adult"
    }
  ],
  "cabinClass": "Economy",
  "baseTotal": 149,
  "promoCode": "WELCOME10",
  "discountAmount": 14.90,
  "finalTotal": 134.10,
  "status": "confirmed",
  "bookedAt": "2026-10-04T10:00:00.000Z"
}
```

> **Session-only:** `_DB.bookings` resets to `[]` on a full page reload. Passwords in `_DB.users` are plain text — do not use real credentials.

#### User (returned from login / register)

```json
{
  "id": "U001",
  "firstName": "Mick",
  "lastName": "Passenger",
  "email": "mick.passenger@luxfly.test",
  "role": "passenger",
  "createdAt": "2024-01-01T00:00:00.000Z"
}
```

`role` values: `"passenger"`, `"travel_agent"`, `"airline_operator"`, `"admin"`

## URL Query Parameters

Pages use query strings to pass search context between screens. The `serve` package routes extension-less URLs to the matching `.html` file.

### Results page (`/results`)

```
/results?origin=SYD&destination=MEL&departDate=2026-11-01
        &passengers=2&adultsCount=2&childrenCount=0&infantsCount=0
        &cabinClass=Economy&tripType=one-way
```

| Param | Type | Notes |
|-------|------|-------|
| `origin` | IATA code | e.g. `SYD` |
| `destination` | IATA code | e.g. `MEL` |
| `departDate` | `YYYY-MM-DD` | |
| `returnDate` | `YYYY-MM-DD` | Only for `tripType=return` |
| `passengers` | integer | Total pax count |
| `adultsCount` | integer | |
| `childrenCount` | integer | |
| `infantsCount` | integer | |
| `cabinClass` | `Economy` \| `Business` \| `First` | Default: `Economy` |
| `tripType` | `one-way` \| `return` | Default: `one-way` |

When `origin` and `destination` are both absent, the page runs in **browse-all mode** — all 176 flights are shown with route badges on each card.

### Flight detail page (`/flight`)

```
/flight?flightId=F001&origin=SYD&destination=MEL
        &departDate=2026-11-01&passengers=1&cabinClass=Economy&tripType=one-way
```

### Passengers page (`/passengers`)

Same params as `/flight`, forwarded from the flight detail "Continue" button.

### Confirmation page (`/confirmation`)

```
/confirmation?bookingId=BK1728000000000&reference=LX-ABC123
              &origin=SYD&destination=MEL&flightId=F001...
```

## Workshop Exercises

### 🟢 Beginner — Basic UI tests

**Exercise 1: Search form validation**
- Navigate to index
- Click Search without filling any fields
- Assert error messages appear for origin, destination, and departure date
- Fill in all fields and assert navigation to results page

**Exercise 2: Flight results**
- Navigate to `/results?origin=SYD&destination=MEL&departDate=2026-11-01&passengers=1&cabinClass=Economy`
- Assert at least one flight card is visible
- Assert `summary-route` text equals "SYD → MEL"
- Click the first Select button and assert navigation to `/flight`

**Exercise 3: Login flow**
- Navigate to `/login`
- Fill in `mick.passenger@luxfly.test` / `Mick1234`
- Assert nav shows user chip with "Mick" and "Passenger" badge

---

### 🟡 Intermediate — Multi-step flows

**Exercise 4: Full booking flow (happy path)**
1. Search SYD → MEL for tomorrow, 1 adult, Economy
2. Select any flight from results
3. On passengers page, fill in valid passenger details
4. Click Confirm & Book
5. Assert confirmation page shows a reference starting with `LX-`

**Exercise 5: Return trip**
- Select the **Return** tab
- Pick depart and return dates
- Assert return date field becomes visible and required
- Assert switching back to One-way hides the return date field

**Exercise 6: Passenger counter**
- Open the passenger picker
- Increment adults to 3, add 1 child
- Assert summary text shows "3 adults, 1 child"
- Search and assert `flight-total-{id}` reflects 4 × price on results

### 🔴 Advanced — Auth, role-gating, and data

**Exercise 7: Coupon application**
1. Sign in as `mick.passenger@luxfly.test`
2. Complete a search and reach `/passengers`
3. Assert the coupon strip shows at least one coupon
4. Click Apply on `WELCOME10`
5. Assert `promo-msg` shows success

**Exercise 8: Role-gated coupons**
- Sign in as `mick.agent@luxfly.test` → assert `AGENT15` visible, `WELCOME10` not shown

**Exercise 9: Invalid coupon**

**Exercise 11: Intercept and override an API endpoint**

Use `page.route()` to replace the flights response before the page loads:

```typescript
await page.route('/api/flights*', async route => {
  await route.fulfill({
    status: 200,
    contentType: 'application/json',
    body: JSON.stringify([
      {
        id: 'T001', airline: 'Test Air', flightNumber: 'TX001',
        origin: 'SYD', destination: 'MEL',
        departureTime: '09:00', arrivalTime: '10:30',
        duration: '1h 30m', stops: 0, stopCity: null,

      }

  });
});
await page.goto('http://localhost:3000/results?origin=SYD&destination=MEL&departDate=2026-11-01&passengers=1&cabinClass=Economy');

```

Alternatively, override handlers at runtime via the exposed MSW worker:

```typescript
await page.evaluate(() => {

  );
});
```
